# Seam list — where the parts did not fit together

> Written as each seam was hit while wiring weeks 3–11 together on **2026-10-20**, then given a status. Entries are
> in the order they were hit; they were not re-ordered or re-worded afterwards except to add the status line.
> **Honesty note:** the brief asks for "Tuesday's unedited seam list". This build was done in one working session,
> not on the Tuesday of a week-long cadence, so this file is dated by what happened, not by the weekday.

| # | Seam (what didn't fit) | Where | Status |
|---|---|---|---|
| 1 | `RetrievalService.retrieve()` had no metadata filter — it could rank, not scope. A date filter had nowhere to live. | W3–4 retriever ↔ date-aware retrieval | **fixed** — optional `where` param added to `retrieve()` and `_bm25_search()`; default behaviour unchanged |
| 2 | `VectorStore.add_documents()` only persists `page` and `section`. Effective dates, product and endorsement id could not be stored through it. | W3–4 ingestion ↔ endorsement metadata | **fixed (bypassed)** — capstone ingest writes the collection directly; `add_documents` left untouched. Accepted debt: two ingestion paths. |
| 3 | Week-11 redaction regex `(LETTERS-){1,3}\d{4}-ALNUM` rewrites endorsement ids like `MOT-END-2023-FLD` to `[ID_REDACTED]`, erasing the thing a citation must name. | W11 redaction ↔ citations | **fixed** — endorsement ids renamed `MOT-END-FLD-2023`; the regex no longer matches them. Fragile: a future id shaped like a policy number will be eaten again. |
| 4 | The same regex also rewrites claim/policy ids inside the stored trajectory, so a trace could no longer be tied back to a claim. | W11 redaction ↔ reproducibility | **fixed** — `scrub(keep_ids=True)` removes personal fields but keeps internal reference ids; free-text logs still use the full redaction. |
| 5 | Week-9 `MCPHost` can neither pass environment variables to the server subprocess nor inject a trace id into tool calls. `stdio_client` also drops custom env unless it is passed explicitly. | W9 host ↔ trace propagation, naive/in-force mode switch | **fixed** — new host code in `capstone/agent.py` (same pattern, `env=` and `trace_id` injection). The Week-9 host file is untouched. |
| 6 | The model must not choose `trace_id` (it would invent one), but the server's tool schema exposes it. | MCP schema ↔ model | **fixed** — host strips `trace_id` from the schema shown to the model and injects it on every call. |
| 7 | Week 3–4 services `print()` progress to stdout. On a stdio MCP server stdout is the protocol channel, so the first run logged `Failed to parse JSONRPC message from server`. | W3–4 services ↔ W9 transport | **fixed** — stdout redirected to stderr while models load and around every retrieve call. Root cause (print in library code) not removed. |
| 8 | Groq free tier caps at 8,000 tokens/minute; one claim costs ~9k tokens through 5–6 LLM turns, so a 36-case suite spent most of its wall-clock waiting. | agent loop ↔ provider quota | **partly fixed** — prompt now asks for the three independent calls in one turn (fewer turns); retry-with-wait on 429. Still the first thing that breaks at volume — see `TEN_X_PLAN.md`. |
| 9 | The model writes `U+2011` (non-breaking hyphen) inside dates and ids ("2024‑08‑11"). Any string match on a date silently fails. | model output ↔ assertions/guard | **fixed** — dashes normalised in the guard before anything is stored or matched. |
| 10 | Guard let "the endorsement **covers** damage to a parked vehicle" through: the pattern list matched "covered" but not "covers". Found in the first live run (trace `cc5cc24bbafe4405`). | guard ↔ model phrasing | **fixed** — see the closed loop in `FAILURE_LOOP.md`. |
| 11 | The model-written `reason` passed to `refer_to_adjuster` is read by a human adjuster but was not passing through the guard. | guard coverage ↔ second output channel | **fixed** — guard applied inside the tool. Trade-off accepted: a replaced reason loses the model's narrative; facts survive because citations, limits and in-force result are code-assembled. |
| 12 | The model passed a hallucinated keyword (`cited_clauses_version`) to `refer_to_adjuster`; the tool errored, the model retried, and my first assembly code then picked the *failed* call as the referral. | agent ↔ tool contract | **fixed** (assembly uses the last successful call). Hallucinated kwargs themselves **accepted** — they surface as argument-validity misses in the trajectory eval. |
| 13 | Week-6 judge prompt was validated on Q&A-over-a-PDF traces (QUESTION/CONTEXT/ANSWER). A triage summary is a different task shape. | W6 judge ↔ integrated output | **see `reports/judge_agreement.md`** — re-validated against hand labels rather than assumed. |
| 14 | Week-5 taxonomy modes (A/B/C: missing date chunk, blanket refusal, off-topic chunk) do not describe agentic failures — there is no "wrong-version citation" or "tool-boundary date drift" in them. | W5 taxonomy ↔ integrated system | **fixed** — taxonomy re-scored from scratch on the integrated runs (`TAXONOMY.md`). |
| 15 | The real corpus (60-page wordings, 2023/2025 endorsement PDFs, 500 claim files) is not in the repo. | corpus ↔ everything | **accepted** — synthetic stand-in with the same structure; consequences listed in `EVAL_REPORT.md` under non-coverage. This is the biggest limit of every number in this repo. |
| 16 | `week9_mcp` servers expose retrieval without a date and with claimant data reachable through the claims-system server; reusing them would break the PII line. | W9 servers ↔ PII requirement | **fixed by not reusing** — new server has no path to claim records at all. |
